# Learning Log

A human-readable record of *why* things in this repo are the way they are:
decisions taken and non-obvious problems solved, so future sessions inherit the
reasoning instead of rediscovering it.

This is a memory aid, **not** a substitute for deterministic guards. Whenever a
lesson can be enforced (linter, test, gate job), do that too — this file explains
the *why*, it never replaces the *how*.

## How to append

Run `node scripts/log-lesson.mjs "the lesson"`. It stamps the date, enforces the
one-line format, and appends. Do not edit this file by hand.

- One lesson per line, 300 characters maximum.
- Format: `- [YYYY-MM-DD]: text`
- Newest entries at the bottom. Never rewrite past entries; add a new line if
  something changes.
- A lesson that does not fit has not been extracted yet — that is an
  investigation. Put it in an ADR or a postmortem and log the one-line lesson
  that points at it.

- [2026-08-30]: ESLint lints the whole staged file, never your diff, so a pre-existing finding in a file you touch blocks your commit: 'I did not write it' is not a position the gate allows. See CLAUDE.md constraint 12.
- [2026-09-05]: EAS defaults a profile to APK only when distribution is internal; a production profile with neither distribution nor buildType silently emits an AAB nobody can sideload, while the docs called it an APK for as long as it existed.
- [2026-09-05]: A release whose diff never reaches the artifact still needs a changelog section, and Keep a Changelog's Internal heading is exactly where it belongs -- the honest entry is that nothing changed for the user, not silence.
- [2026-09-08]: Reusing a reviewed taxonomy is not free when two callers mean different things by the same status code: 'any 4xx is permanent' is right for reconcile and would have silently drained the diagnostics queue on the 404s a not-yet-shipped endpoint returns.
- [2026-09-09]: An additive, nullable migration is a minor bump, not a major: reverting the APK leaves the columns unread instead of stranding the catalogue.
- [2026-09-10]: A repair step that lowers drizzle's max __drizzle_migrations.created_at makes the migrator re-run applied ALTERs; SQLite rejects the duplicate column and startup dies. It lay dormant until a new migration raised the readiness version.
- [2026-09-10]: Ledger position is not migration identity: a device that skipped a migration appends later ones into the gap, so any repair inferring identity from row order re-runs an ALTER and bricks startup. Pin the gate instead and let idempotent repair steps converge.

- [2026-09-22]: Ordering timeouts is not tuning: when an inner lock wait and the outer operation deadline hold the same value, the inner bound is unreachable by construction and a transient lock surfaces as a fatal failure.
