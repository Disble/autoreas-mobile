### Bounded technical approach

- Keep `withLocalWrite` and the existing file-keyed write boundary. Its callback already receives the raw `SQLiteDatabase`; it does not need a new asynchronous transaction abstraction. Preserve transaction release and validation.
- Replace synchronous Drizzle I/O inside the selected anime action path with the existing connection's `getFirstAsync` / `runAsync` / `execAsync` operations, preserving SQL predicates, schema parsing and patch builders. Android's installed Expo bindings explicitly run the corresponding methods on `Dispatchers.IO`.
- Accept the action and publish its optimistic value before waiting for storage. Integrate the minimum transient projection into the existing action/read-model surface; it is not a second durable log. Retire acknowledged projected work when the local read model covers it, not by forcing a wait for Bridge. Newer accepted actions survive older local or remote completions.
- Remove the chapter pending-disable/drop plumbing as part of that same coherent UI behaviour change, not as an intermediate "unlocked but no optimistic state" implementation.
- Incorporate Bridge corrections through existing data/sync functions. Change synchronous I/O in the touched correction/application path where needed; do not turn this into a repository-wide Drizzle or read-query replacement. Reuse the current native staging and reactive drain rather than inventing another runtime.
- Reuse existing failure feedback. Do not add badges, settings or new product recovery flows. A caller deadline is not proof that the underlying write was cancelled; do not open the write boundary or retry the action as new because that deadline expired. Specify and test eventual completion versus true rollback in the affected path.
- Preserve grade/state behaviour and other consumers of shared mutation helpers. The explicit new rapid-input example concerns chapters; do not impose a new busy gate on other actions or expand this task into unrelated feature redesign.
