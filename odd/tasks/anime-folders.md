# anime-folders

Objective: open each anime's folder on the tablet (Samsung My Files) and its page from the anime card, after the user picks the anime root once with the Android folder picker.
Branch: `feat/anime-folders` from `dev` (6540aec). Delivery: work-unit commits, local merge only (`ask-on-risk`). Test runner: Jest (`bunx jest`), gate `npx lefthook run pre-commit`.
Sources: approved flow canvas https://claude.ai/artifact/JMTgyGaUG7CKHFkVvkZLHr (board titles are current; sticky notes n01/n02 predate the onboarding correction), PoC commit `0157db3` on `poc/open-device-folder` (reference only, not merged), bridge contract on bridge branch `feat/library-root`.

## Specs

- **S1 — Root selection (onboarding).** The user picks the anime root with the Android folder picker (SAF `pickDirectoryAsync`), opened already at `SD card › Videos › Anime` when that folder exists (INITIAL_URI, verified via adb). The guided BottomSheet ("Elige tu carpeta de anime", canvas 02) never opens by itself, not on launch and not after an update; it opens only from "Elegir carpeta" in the hint banner. User: "El 'Elegir carpeta' es literalmente el 'onboarding'". "Ahora no" closes it. Cancelling the picker or the grant changes nothing. Copy as in canvas 02: "Selecciona la carpeta de esta tablet donde guardas los animes, por ejemplo SD card › Videos › Anime. Autoreas busca dentro la carpeta de cada anime para abrirla con un toque.", steps "Entra en la carpeta que contiene tus animes", "Toca «Usar esta carpeta»", "Toca «Permitir» en el aviso de Android", note "Solo lee los nombres de las carpetas. No abre, mueve ni borra tus videos."
- **S2 — Persistence.** The chosen root (tree URI) and the dismissed hint survive app restart and tablet reboot (both verified with the PoC). Stored in the singleton `app_preferences` row, not in a side file. The persisted grant is taken by the picker (`takePersistableUriPermission`).
- **S3 — Folder index and resolution.** Index folder names below the root up to 3 levels, skipping hidden folders (name starts with `.`) and files. Resolve each anime in this order: relative path (`folderRelative` from the bridge, see S8) → exact folder name (basename of `carpeta`, case-insensitive) → normalized name. A name that matches more than one folder resolves to nothing. A folder more than one anime resolves to opens for none of them (canvas 08, approved copy: "Si dos animes comparten el nombre de una carpeta, aparecen aquí y ninguno muestra el botón hasta que se distinga en la PC."). The folder button shows only when exactly one folder resolves. Device baseline: 24 folders, 22 animes with folder, 1 folder without anime (Suzumiya Haruhi no Yuuutsu BD Castellano), subfolders of a matched folder (Mini Episodes) are content, not findings.
- **S4 — Card buttons.** Page and folder icon buttons sit bottom-left in the action row, in the same row as − N + or Reanudar (canvas 06). The meta row stays text only. The page button shows only for an `http(s)` URL with a host (`descargado` shows nothing). Without a configured, readable root no folder button shows anywhere (canvas 01).
- **S5 — Opening the folder.** Opens Samsung My Files at the folder (`LAUNCH_MY_FILES` + `START_PATH`). User: "es suficiente con que cuando este en split, abra en split scren": in split screen it opens in the other half, reusing the My Files already there (verified). From full screen, opening full screen is accepted. Forcing split from full screen, or a Settings option for it, is out of scope.
- **S6 — Banners (list screen).** Hint banner, accent soft, until a root is set or "Ahora no" dismisses it for good: "Abre la carpeta de cada anime desde la tablet" / "Elige una vez dónde guardas los animes. Autoreas solo lee los nombres de las carpetas." with "Ahora no" (ghost, readable contrast) and "Elegir carpeta" (primary). Lost-access banner, danger soft, when the root can no longer be read: "No se puede leer la carpeta de anime" / "La tarjeta SD no está o Android quitó el permiso. Los botones de carpeta vuelven cuando la elijas de nuevo." with "Elegir de nuevo" (goes straight to the picker). Page buttons keep working. User on style: "Puede quedarse con el background rojo, pero no el borde con color. Creo que en terminos de HeroUI es el tipo soft."
- **S7 — Settings.** New card "Carpetas de anime" (canvas 05): Carpeta `SD card › Videos › Anime`, Encontradas "22 animes con carpeta", Revisado "hace un momento", the "1 carpeta sin anime" row with "Ver detalle", and the actions "Volver a buscar" (reindex) and "Cambiar carpeta" (picker). After picking, a confirmation "Listo: 22 animes ya abren su carpeta desde la tarjeta." "Ver detalle" opens the read-only screen "Carpetas de anime" (canvas 08): totals (carpetas / con anime / sin anime), the lists "SIN ANIME", "CON MÁS DE UN ANIME", "CON ANIME" with how each matched, and the explanatory copy from the canvas. No manual linking (option D is out of scope).
- **S8 — `folderRelative` from the bridge.** The bridge sends optional `folderRelative` (`/`-separated path below its library root) on MobileAnime for the list, detail, and every changes-feed snapshot; the WS payload is not decorated. Mobile stores it in a new column. It is coupled to `folder`: take it from the snapshot whenever `changed_fields` contains `folder` (absent = null), on create, and in the full-resync diff. No `folderRelative`-only events exist. Animes without it fall back to name matching (S3).
- **S9 — Responsiveness.** Device evidence: the synchronous SAF walk took 3.0–4.6 s warm and 14.7 s right after a reboot, froze the UI, and ran twice at launch. Indexing must not freeze the UI, must not run twice concurrently, and the list must render with the last known index while a refresh runs. (Derived from device evidence; the user approved going to official with the PoC findings.)
